# Проверка результата

Дата: 02.11.2026. Среда: Python 3.12.14, настоящая PostgreSQL 16 в изолированном Docker-контейнере. Реальный токен MAX не предоставлен и не использовался.

## Выполнено

**31 тест пройден**, 0 ошибок; покрытие Python-кода — **80%**, бизнес-сервиса — 89%, чистых расчетов — 94%, Webhook — 100%. Покрытие CLI в pytest отсутствует, но команды migrate/web/worker проверены фактическим запуском контейнеров.

Проверены:

- Расчеты смен, перерывов и чистого времени; отсутствие незакрытых смен в итогах.
- Смена через полночь: обрезка самой смены и пересекающего полночь перерыва по отчетному дню; это проверено и чистой функцией, и реальными операциями сервиса с PostgreSQL.
- Границы недели, месяца и года, UTC и локальные даты; 23-часовой день при переходе DST.
- Регистрация и запрет учета до одобрения; блокировка; запрет администраторских команд сотруднику; доступ только к собственным отчетам и сменам.
- Начало/окончание работы, начало/окончание перерыва; завершение во время перерыва; отказ при нарушении порядка отметок.
- 16 конкурентных попыток начала смены и ограничение уникальности БД; одновременная повторная доставка одного Webhook.
- Повторная обработка одного message/callback не изменяет учет второй раз. Старая версия кнопки не создает новую смену. Разные нажатия с одинаковым ID кнопки различаются по времени события.
- Исправление своей завершенной смены с причиной; запрет чужого исправления и одобрения сотрудником; отсутствие изменения до одобрения; применение полного списка перерывов.
- Аудит с автором, администратором, причиной, датой, старыми/новыми значениями; отказ для устаревшей заявки и пересечения другой смены; отклонение без изменения учета.
- Подлинность Webhook, отклонение групповых событий, callback без исходного контекста диалога, неверных/слишком больших входных данных.
- Постоянные inbox/outbox, повторная отправка после сбоя, сохранение токена загруженного файла между попытками, проверка блокировки перед отправкой персональных данных.
- Задержка отправки одному получателю не блокирует других; порядок ответов одному пользователю сохраняется.
- CSV с UTF-8 BOM, русскими заголовками и защитой ФИО от формул Excel.
- HTTP-контракт MAX на MockTransport: адрес, Authorization без query-токена, подписка с секретом, multipart-поле data, токен файла, приватный user_id, callback answer, 429 Retry-After и attachment.not.ready, отказ загрузки на посторонний URL.
- Повторный запуск миграций.

При запуске тестов есть одно предупреждение зависимости Starlette о будущем переходе TestClient с HTTPX на HTTPX2; тесты с зафиксированными версиями проходят.

## Фактический Docker smoke test

- Dockerfile собран с зафиксированными зависимостями, без реального токена.
- `docker compose up -d --build`: PostgreSQL healthy, migrate exited 0, web и worker работают от непривилегированного пользователя.
- `GET /health`: HTTP 200, `{"status":"ok"}`.
- `POST /webhook` без секрета: HTTP 403.
- В тестовой БД созданы открытая смена и открытый перерыв; контейнеры web и worker перезапущены. Обе записи остались открытыми с исходными UTC-отметками.
- Журнал worker показывает успешный запуск. Обмена с реальной платформой в этом тесте нет.

2. Регистрация подписки на вашем публичном HTTPS endpoint и фактическая доставка с X-Max-Bot-Api-Secret.
3. Реальное отображение всех шести кнопок в клиентах MAX и callback-уведомления.
4. Полный сценарий двух настоящих пользователей: регистрация, одобрение, смена, перерывы, блокировка, исправление и отчет.
5. Загрузка CSV на фактический MAX upload-host и получение файла в личном диалоге; при необходимости проверка/добавление нового официального upload-host в allowlist.
6. Открытие полученного CSV в настольном Excel. Кодировка, BOM, разделитель и защита формул проверены программно; реальный Excel здесь не запускался.
7. Работа TLS с цепочкой сертификатов вашего API/endpoint, включая сертификаты Минцифры при необходимости.
8. Поведение настоящего MAX при его собственных ограничениях частоты, временных отказах и повторной доставке. Эти сценарии проверены имитацией HTTP-ответов и событий, а не созданием нагрузки на платформу.
